Scene Director 2.1.0 for OBS Studio 32.2.x (Windows x64)
========================================================

Scene Director drives Synesthesia over OSC. It follows Music Director's beat clock
(director_clock) and sends Synesthesia's playlist Next on breakdowns and drops, landing on the
same beat as the palette change and the clip cut, and Next / Previous from a dock button or an
OBS hotkey by hand. It listens on Synesthesia's OSC output to confirm each scene change. It is
part of Director 2.1.0 and ships in the suite zip, Windows x64 only.

It adds:
  - a source "Scene Director"
      It renders nothing (0 x 0, no video output). It holds the OSC settings and drives the
      sends, so it must be added to a scene.
  - a dock "Scene Director"
      The clock and section, the OSC link, host and ports, counters, Next / Prev, the
      breakdown and drop switches, the cooldown, Scene lead, the event map and the log.
  - the hotkeys "Scene Director: Next scene" and "Scene Director: Previous scene"
      OBS Settings > Hotkeys.
  - the event map
      %APPDATA%\obs-studio\plugin_config\scene-director\event-map.json

Needs Music Director 2.1.0 for the beat clock, and Synesthesia Pro for OSC (tested with
Synesthesia 1.25.4.189). Without Music Director, Scene Director idles: no automatic sends,
one log line, the dock reads "Waiting for Music Director"; the dock buttons and the hotkeys
still send.


1. Install
----------
1. Close OBS.
2. Install the suite: unzip director-2.1.0-windows-x64.zip (from
   https://github.com/EnZhm/director/releases) and copy its four folders into
     C:\ProgramData\obs-studio\plugins\
   so that these files exist, among others:
     C:\ProgramData\obs-studio\plugins\music-director\bin\64bit\music-director.dll
     C:\ProgramData\obs-studio\plugins\scene-director\bin\64bit\scene-director.dll
     C:\ProgramData\obs-studio\plugins\scene-director\data\locale\en-US.ini
3. Start OBS. Help > Log Files > View Current Log should show
     [scene-director] plugin loaded successfully (version 2.1.0)
     [music-director] plugin loaded successfully (version 2.1.0)


2. First run: Synesthesia over OSC
----------------------------------
  DJ mixer -> OBS audio -> Music Director clock -> Scene Director -> OSC -> Synesthesia input
                                                                 <- OSC <- Synesthesia output

1. Build the playlist in Synesthesia with the scenes in the order you want, and set the
   playlist's own transition as you like.
2. In Synesthesia, open Settings > OSC:
     Input: on        Input port: 7000      (Scene Director's Send port)
     Output: on       Output address: 127.0.0.1
                      Output port: 9001     (Scene Director's Feedback port)
   The Output port must NOT be the Input port. A freshly configured Synesthesia can have
   its output pointed at its own input, which hides all feedback. "Output controls" and
   "Output audio variables" are not needed.
3. In OBS add a "Scene Director" source to a scene.
4. Open the Scene Director dock (Docks menu > "Scene Director"). Host 127.0.0.1, Send 7000,
   Feedback 9001 are the defaults; change them and press Apply if Synesthesia uses other
   ports.
5. Press Next. The playlist moves on and the link chip turns green ("OSC linked").
6. Play some music. On the next breakdown and on the next drop, Scene Director sends Next
   on the beat and the playlist moves by itself.


3. The Scene Director dock
--------------------------
Docks menu > "Scene Director". It drives the first Scene Director source in the scene
collection; its refresh timer also steps the engine, so the automatic sends keep working
when the source is not in the active scene.

- Top: the clock ("Following Music Director's clock" or "Waiting for Music Director") and
  the section chip (GROOVE / BREAKDOWN / DROP).
- Link chip:
    "OSC linked"  green  Synesthesia's feedback arrived in the last 5 seconds, or a send
                         was confirmed
    "Sending"     grey   sends go out, no feedback seen; sends still work
    "OSC error"   red    a socket error or a send queue overflow
  A missed confirmation never turns the chip red.
- Host / Send / Feedback with Apply. A feedback port equal to the send port is not saved.
  An amber line reports a feedback port equal to the send port (set Synesthesia's OSC
  Output port to a different port, default 9001) or a feedback port in use (retried every
  5 seconds). Sending continues in both cases, without feedback.
- Traffic: sent, received, dropped.
- Confirm: last and median latency, confirmed, missed, mismatched, external.
- Next / Previous: send now. A manual send always fires.
- Next on breakdown, Next on drop, Cooldown: the event map entries breakdown-next and
  drop-next (enabled, min_interval_beats).
- Scene lead (ms): send the automatic message this much early, to cover Synesthesia's own
  scene-load time. Default 0. The target beat does not move.
- Event map: the file path, Reload, Open folder and the last load summary.
- Log: every send with route, args, beat, reason, seq and confirmation result.

The OSC settings are saved with the scene collection, in the Scene Director source, and are
also in the source's properties (right-click the source > Properties): Host, Send port,
Feedback port (0 = no feedback), Confirmation timeout (ms, default 2000), Scene lead,
Sync offset.


4. When it sends (default event map)
------------------------------------
- Breakdown: /playlist/next on the breakdown's landing beat (section_beat), minus Scene
  lead.
- Drop: /playlist/next on the drop's landing beat, minus Scene lead.
- Groove: nothing.
- Cooldown: an automatic breakdown or drop send within 16 beats of the previous send
  (automatic or manual) is held back and written to the log as "suppress". Forced sections
  (Force breakdown, Drop now) bypass it.
- Next / Previous from the dock or the hotkeys: /playlist/next or /playlist/previous at
  once (150 ms debounce).
Each section edge sends once, even with several Scene Director sources.

Other actions (a scene launch with a preset, a control bang on every phrase, ...) are set in
event-map.json. The full reference is the "Event map" section of the suite README:
  https://github.com/EnZhm/director#event-map
A syntax error in the file keeps the last good map; a bad entry is skipped and logged.


5. Confirmations
----------------
Synesthesia reports the scene it loaded on its OSC output. Scene Director logs
  [scene-director] confirm <scene> in <ms> ms
  [scene-director] no confirmation for <route> after <ms> ms
  [scene-director] mismatch: sent <a>, Synesthesia reports <b>
  [scene-director] external scene change: <scene>
Confirmations are best-effort: Synesthesia does not answer every command, so a missed
confirmation does not mean the scene did not change. Scene Director never resends and never
waits for a confirmation. An external change (for example from a controller mapped in
Synesthesia's MIDI panel) is logged and left alone.


6. Upgrading from 2.0
---------------------
- MIDI out is removed. No virtual MIDI port (loopMIDI or a Windows MIDI Services loopback)
  is needed; set up OSC as in section 2.
- The 2.0 MIDI settings stay in the scene collection, unused. The log says once per source:
    [scene-director] '<source>': MIDI out was removed in 2.1; Synesthesia is driven over
    OSC (<host>:<port>)
- The breakdown and drop switches and the cooldown seed event-map.json on the first run.
  Scene lead and Sync offset are kept.
- A controller that moved the playlist through MIDI Director is now mapped in Synesthesia's
  own MIDI panel: devices tab "refresh connected devices", then map the playlist "next" and
  "previous" in the scenes tab.
- Rollback: the Director 2.0.0 zip; the 2.0 settings are still in the scene collection.


7. Troubleshooting
------------------
- No dock in the Docks menu: the plugin did not load. Check the log for the "plugin loaded
  successfully" lines and the folder layout in section 1.
- The playlist does not move when Scene Director sends: check Synesthesia Settings > OSC:
  Input on, Input port = the dock's Send port. Turn on "log OSC" in Synesthesia's console to
  see what arrives.
- The chip stays grey ("Sending") but the playlist moves: no feedback arrives. Check
  Synesthesia's Output (on, address 127.0.0.1, port = the dock's Feedback port, different
  from the Input port). Sending works regardless.
- Amber "Feedback port N is in use": another program holds that port. Pick another port in
  both Synesthesia's Output port and the dock.
- Synesthesia's OSC settings are in its Data/preferences.json: OSC_INPUT, OSC_INPUT_PORT,
  OSC_OUTPUT, OSC_OUTPUT_ADDRESS, OSC_OUTPUT_PORT, OSC_OUTPUT_AUDIO, OSC_OUTPUT_CONTROLS,
  OSC_OUTPUT_CONTROLS_FORMAT.
- Nothing is sent on a breakdown or a drop: check Next on breakdown / Next on drop in the
  dock, and the cooldown; the log says "suppress" when the cooldown holds a send back.
- Everything fires twice: the same pad drives Synesthesia's playlist in its MIDI panel and
  a Scene Director hotkey. Bind it in one place only.
- Scenes arrive late: raise Scene lead so the message is sent earlier.
- Synesthesia was updated: its OSC API is "subject to change". Check that Next still moves
  the playlist and the chip still turns green.


8. Uninstall
------------
Close OBS, then delete the four Director folders from
  C:\ProgramData\obs-studio\plugins\
Your scene collections and sets are kept.
